# conf-agent 配置目录版本管理与清理

## 1. 概述

`conf-agent` 每次从 `ai-gateway-api` 拉取到新配置后，会创建带版本号后缀的临时配置目录（如 `mod_ai_token_auth_20260730144012`），并通过符号链接 `mod_ai_token_auth` 指向最新目录。这种设计使得 BFE 可以在不重启的情况下完成热加载，同时保留历史版本便于回滚。

但随着运行时间增长，历史版本目录会不断堆积。本文档描述 `conf-agent` 对配置目录的版本管理机制，以及过期目录的清理策略。

---

## 2. 目录版本机制

### 2.1 临时目录命名

临时目录由 `conf_reload/file_store.FileStore.tmpDir` 生成：

```go
func (fileStore *FileStore) tmpDir(version string) string {
    return fileStore.ConfDir + "_" + version
}
```

其中 `version` 来自配置文件内容中的 `Version` 字段（非数字字符会被去除）。例如：

```text
ConfDir:  /home/work/bfe/conf/mod_ai_token_auth
version:  20260730144012
tmpDir:   /home/work/bfe/conf/mod_ai_token_auth_20260730144012
```

### 2.2 符号链接切换

`UpdateDefaultConfDir` 负责切换正式配置路径的符号链接：

1. 解析当前 `ConfDir` 的符号链接目标；
2. 删除旧符号链接；
3. 删除旧符号链接指向的真实目录（即上一个版本目录）；
4. 新建符号链接指向最新临时目录。

切换后文件系统示例：

```text
/home/work/bfe/conf/
├── mod_ai_token_auth -> /home/work/bfe/conf/mod_ai_token_auth_20260730144012
└── mod_ai_token_auth_20260730144012/
```

### 2.3 版本目录标识

为了安全识别 `conf-agent` 生成的版本目录，避免误删用户手动创建的目录，每个临时目录创建时会写入标识文件 `.conf-agent-version`：

```go
markerFile := filepath.Join(tmpDir, ".conf-agent-version")
os.WriteFile(markerFile, []byte(version), 0644)
```

清理逻辑通过该标识文件判断目录归属。

## 3. 清理策略

### 3.1 清理时机

清理在 `UpdateDefaultConfDir` 成功建立新符号链接后执行，确保 BFE 已经切换到新配置。

### 3.2 保留版本数

保留的历史版本数量通过配置项 `VersionKeepCount` 控制：

| 配置项 | 位置 | 默认值 | 说明 |
|--------|------|--------|------|
| `VersionKeepCount` | `Basic` | 2 | 全局默认值 |
| `VersionKeepCount` | `Reloader` | 继承 `Basic` | 单个 Reloader 可覆盖 |

最小值为 `1`，即至少保留当前激活版本。若配置小于 1，启动校验失败。

### 3.3 清理步骤

```go
func (fileStore *FileStore) cleanupOldVersions(ctx context.Context, keep int) error
```

1. 解析当前 `ConfDir` 的符号链接目标 `currentTarget`；
2. 遍历 `ConfDir` 的父目录；
3. 筛选候选目录：
   - 名称前缀为 `filepath.Base(ConfDir) + "_"`；
   - 目录内存在 `.conf-agent-version` 文件；
   - 不是当前符号链接目标；
4. 按目录修改时间倒序排序；
5. 保留前 `keep` 个，删除其余；
6. **兜底清扫无标记空目录**（conf-agent#20）：对无 `.conf-agent-version` 且为空的同名目录（中断的 Store 产生的半成品）一并删除；非空无标记目录保留（可能是用户手工维护的目录）；
7. 记录删除数量与错误。

### 3.4 为什么保留多个版本

- **BFE 句柄安全**：BFE 热加载后可能仍持有旧配置文件的句柄，立即删除旧目录在某些平台（尤其是 Windows）可能失败；
- **快速回滚**：保留上一版本可在异常时通过切换符号链接快速恢复；
- **容错**：避免单次清理失败导致配置完全不可回退。

---

## 4. 异常场景处理

| 场景 | 处理 |
|------|------|
| `ConfDir` 是正常符号链接 | 删除旧链接和目标，建立新链接。 |
| `ConfDir` 是普通目录 | 重命名为 `ConfDir_<timestamp>.backup` 并保留，建立新符号链接。 |
| `ConfDir` 不存在 | 直接建立新符号链接。 |
| `ConfDir` 是损坏的符号链接 | 删除损坏链接，建立新链接。 |
| 清理时目录被占用 | 记录错误，不中断主流程；该目录会在下一次清理时重试。 |
| 存在无标记空目录 | 随清理步骤 6 一并删除（多为中断 Store 产生的半成品）；若非空且无标记则保留，避免误删用户手工目录。 |

## 5. 配置示例

```toml
[Basic]
VersionKeepCount = 2

[Reloaders.mod_ai_token_auth]
VersionKeepCount = 3  # 该模块保留 3 个版本

[Reloaders.tls_conf]
# 未设置，继承 Basic.VersionKeepCount = 2
```
